# Mac 与 iPhone 的 Logo 和界面一致性

状态：设计定稿 v1.0。2026-10-10 用户已批准总体方向及两轮共七项选择。本文补充 iPhone 远端开发规格，新增两端视觉一致性和客户端完成未读行为；原有首版功能范围继续适用。文档已形成，界面改造尚未实施。

## 已确认的方向

- 以现有 Mac 版为视觉基准，两端沿用现有 herdrm Logo、统一正式应用名称。
- 共用视觉资源和主题定义，包括明暗配色、字体层级、圆角、分隔线、选中效果及 Mac 当前的橙色强调色。
- 统一开发机、Space 和 Agent 的图标、列表层级和状态含义；连接、失败与恢复提示使用一致的视觉语言。
- Mac 保留侧栏与终端并排；iPhone 使用列表进入终端，保留 Agent、项目预览和设置入口，并按触控和键盘使用适配。
- iPhone 首版仅操作已有 Agent，沿用已批准的 SSH 配对、Agent 操作与 App 内预览范围。

这里的一致性指相同品牌、信息层级、状态含义和组件视觉。按钮尺寸、页面布局与导航方式按各平台操作方式适配。

## 现有事实

- Mac 图标源位于 Resources/AppIcon/herdrm-icon.svg 与 herdrm-icon-1024.png；Mac 另有 AppIcon.icon 配置。
- Mac 的 Theme.swift 定义明暗配色，目前使用 AppKit；视觉定义需要提取后才能被 iOS 使用。
- MobileRootView.swift 采用默认 SwiftUI 列表和导航组件；当前 iOS target 没有接入 Mac 的图标和主题资源。
- Mac 已有系统/浅色/深色外观设置，终端跟随 App；iPhone 终端当前固定深色。
- Mac 已接入中英文资源并提供应用内语言设置；iOS target 尚未接入同一语言资源。
- Mac 完成状态区分未读蓝点和已读无标记；iPhone 完成状态恒为绿色勾，尚无对应未读状态。因此复用完成标记需要明确行为范围。
- Mac 未读是 GUI 本地内存状态，服务端没有 viewed 状态。首次快照中的历史完成不会标未读；当前 Mac 会在完成转变时标记，即使 Agent 已被选中，并在切离旧选中 Agent 时清除。重启丢失标记，重连期间完成的任务不保证提醒。
- 正式 iPhone 目前采用列表进入终端；已验收 POC 的底部三入口尚未接入正式 target。已批准的手机布局方向将用于正式界面。
- #1 开发机配置的实现未改造主界面；已有 18 个功能任务没有单独覆盖完整视觉统一。

## 第一轮已确认

1. 外观模式：沿用 Mac 的“跟随系统 / 浅色 / 深色”设置，默认跟随系统，App 和终端均跟随所选模式。
2. 界面语言：共享中英文资源，沿用 Mac 的“跟随系统 / 中文 / English”设置；中文下统一工作区、开发机等术语，保留 Agent 名称，不翻译远端名称与终端输出。
3. 手机列表密度：默认舒适的触控间距，接近 Mac 的信息层级，减少当前大标题和大块卡片；保留长名称和状态可读性。
4. 实施顺序：完成 #1 真机表单验收后，在 #2 前增加独立的视觉基础任务（图标、主题、基础控件）；各功能任务完成时使用该基础做页面，最后集中做两端截图对比与真机验收。
5. 完成状态：两端采用 Mac 的完成未读/已读区分；手机增加对应状态，完成未读用蓝点，查看后清除未读标记，状态详情仍可读取“已完成”。这需要记录状态行为，不只涉及样式。

用户明确答复：“5 项都按推荐”。

## 第二轮已确认

6. 客户端边界：Mac 和 iPhone 分别记录自己的已读状态，规则和样式一致；Mac 查看后不清除 iPhone 蓝点。跨客户端同步留待后续。
7. 提醒生命周期：两端都保存各自已经产生的未读标记，首次连接不把已经完成的历史任务全部标为未读。当前客户端观察到新一轮完成，且用户未在前台查看该终端时显示蓝点；进入对应终端并成功显示内容后清除，连接恢复页、预览页和后台选中不算查看。标记按开发机和 Agent 保存，锁屏或重启不会单纯因连接恢复而清除。这会改进 Mac 当前的内存存储和“切离后清除”行为，使两端遵循同一套规则；客户端未观察到的断线期间完成，不承诺补发提醒。

用户明确答复：“2 项都按推荐”。两端分别记录自己的未读状态；现有 Mac 的清除时机和存储方式需要同步改进。

## 后续验收范围

使用相同开发机和 Agent 数据，对比两端的空状态、设备列表、Agent 列表、终端、连接失败与恢复提示；比较浅色和深色截图。在 iPhone 13 / iOS 18.7.3 检查触控、键盘、长中文名称和文本放大。项目网页保持项目本身的样式，统一的是 App 的预览导航与状态提示。

## 设计决策记录

已读状态属于客户端，[ADR 0001](../adr/0001-client-owned-agent-read-state.md)记录状态边界及取舍。术语参见根目录 [CONTEXT.md](../../CONTEXT.md)。

## 实现边界

1. **视觉资源与主题**：提取 Mac 的配色和视觉层级为两端可用的定义，沿用现有 Logo 源素材，分别接入平台要求的图标资源。AppKit 和 UIKit 的外观解析保留在各自适配处；共享层不依赖任一平台专属框架。
2. **语言与外观设置**：共享中英文文案及相同选项，设置在当前客户端保存。切换外观和语言不重新建立 SSH 连接，不清除 Agent 草稿或预览目标。网页内容的主题和语言仍由项目网站决定。
3. **状态与未读规则**：两端共用状态到颜色、标记和文字的映射，以及完成未读的判断规则；当前客户端负责保存标记和提供前台可见性。标记属于开发机与 Agent，不能仅按显示名称索引。
4. **页面适配**：两端保留各自导航和布局组件，使用共同的主题、图标和状态组件。移动端设备表单、Agent 列表、终端、设置和后续预览导航均接入这些定义。
5. **可用性与错误状态**：手机可点击区域至少 44 点，支持系统文字放大；放大后允许换行及增加行高。连接失败和恢复提示不得覆盖已保存选择，也不能将恢复中的 Agent 显示成“没有选择”。状态须可通过文字或辅助功能读取，不能仅靠颜色表达。

## 完成未读的具体场景

| 场景 | 两端统一行为 |
| --- | --- |
| 首次连接，列表中已有完成 Agent | 以当前状态作为基线，不产生一批历史未读提示 |
| 已知 Agent 从非完成变为完成，当前终端不可见 | 标为完成未读并保存蓝点 |
| 前台正在查看对应 Agent，当前终端内容已成功显示 | 本次结果视为已读，不产生蓝点 |
| 选择 Agent 后仍在连接、恢复或等待终端内容 | 保留未读，选择本身不代表查看 |
| 已有蓝点，进入前台并成功显示对应终端内容 | 清除该客户端的未读标记并保存 |
| Mac 查看完成结果，iPhone 尚未查看 | 只清除 Mac 标记，iPhone 保留自己的标记 |
| 锁屏、退出 App 或重启后恢复 | 保留此前已产生的未读标记；仅恢复连接不算已读 |
| 权威快照确认 Agent 开始新任务或已被删除 | 清除旧完成标记；断线或临时缺少数据不算删除 |
| 切换开发机、遇到同名 Agent | 按开发机与 Agent 身份隔离标记 |
| 断线期间任务完成且客户端没有观察到转变 | 不保证产生新提醒；恢复后显示真实运行状态 |

“终端内容已成功显示”指当前前台对应 Agent 的可用终端画面，不能用选中 ID、缓存占位页或上一个连接的画面替代。实现时应使用可验证的终端画面就绪信号确认；失败时保留蓝点，避免误标已读。

## 验收条件

- 两端显示同一正式名称和同一 Logo 构图，手机安装图标不为空；保留各平台系统裁剪与表现。
- 对比相同数据的浅色与深色截图，强调色、状态图标、文本层级、选中效果和分隔线一致。
- 中文与英文设置生效，未翻译远端名称与终端输出；设备为空时不再仅提示“添加 Mac”，支持用户的 Linux 开发机语境。
- iPhone 列表取消当前的大块空状态和大标题视觉，层级接近 Mac，同时通过真机点击、长名称和文字放大检查。
- 明暗设置对 App 和终端共同生效；中途切换保持连接、Agent 草稿和预览目标。
- 未读行为覆盖以上场景，尤其验证终端未恢复不清除、冷启动保留、跨开发机隔离和两客户端互不清除。
- Mac 的侧栏与终端布局保留；除明确批准的未读改进外，原有连接和终端行为通过相关回归检查。
- 图标和主题本身通过资源检查、两端构建与截图验收；未读规则使用行为测试，不为纯视觉值编写镜像测试。
