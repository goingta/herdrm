# iPhone 远端开发：SSH 配对、Agent 操作与 App 内预览

状态：规格草案 v0.4（首版范围已确认）；更新于 2026-10-10。SSH 配置与配对、已有 Agent 操作及 App 内预览三个方向的产品范围均已确认；实现方案和验收指标保留为建议。原型验证通过；依据本规格拆出的 18 个实施任务已获批准并发布到 GitHub，规格正文仍保存在仓库。

本文用“已确认”标记会话和真机验证形成的决定，用“首版建议”标记本轮提出、仍可调整的产品范围。测试入口已向用户征求意见，答复前保持为建议。

## Problem Statement

用户的代码和 Agent 运行在远端 Linux 开发机。现在需要通过 Mac 的 SSH 配置登录开发机，在 herdr 中给 Agent 输入 prompt，再通过转发访问 Agent 启动的项目服务。iPhone 上希望完成同一条工作流程：连接开发机、操作 Agent、在 App 内检查运行效果。

现有 Safari 访问 herdr-web-ui 的方式已经可达，但返回前台时会整页重新加载，打断开发过程。iPhone 原生原型已经验证 SSH 认证、工作区及 Agent 列表、中文 prompt、终端和项目预览；锁屏返回时出现的 “No Agent Selected” 闪屏也已修复并通过复验。正式版本需要把这些能力整理成可配置、可恢复、可诊断的日常工具。

## Solution

### 已确认的产品路线

在现有 herdrm 的 HerdrMobile 中实现原生 iPhone 客户端。开发任务继续由 Linux 上的 herdr 和 Agent 执行；App 提供原生终端和操作入口，项目网页在 App 内预览。基线覆盖 iOS 18，验收设备包括用户的 iPhone 13 / iOS 18.7.3。

基本流程：配置开发机 → 登记手机公钥 → 校验连接 → 选择工作区与 Agent → 发送 prompt / 查看终端 → 获取项目服务端口 → App 内预览 → 锁屏或切换网络后回到原来的开发上下文。

后台与恢复属于三个方向的共同约束：远端任务持续执行；App 保存操作上下文，回前台重建连接。进程仍在时保留终端原画面；冷启动恢复已保存的选择、草稿和预览目标。普通 iOS App 的无限后台常驻不作为产品承诺。

### 三个方向的首版范围

| 方向 | 首版能力 | 后续版本扩展 |
| --- | --- | --- |
| SSH 配置与配对（入口已确认） | 手动新增、编辑、删除开发机；直连或 HTTP CONNECT；手机独立密钥；复制登记命令；主机指纹确认；分阶段连接诊断 | 导入 SSH config、SSH 跳板、代理认证、导入已有私钥均留待后续版本 |
| Agent 操作（范围已确认） | 工作区与已有 Agent 列表；原生终端；中文及多行 prompt；必要控制键；按 Agent 保存草稿；恢复选中 Agent | 创建、重命名、关闭 Agent，以及创建工作区均留待后续版本 |
| App 内预览（范围已确认） | 输入远端服务端口或完整 HTTP/HTTPS URL；命名保存并关联工作区；每次一个活动预览；网页导航；相对路径 API/WebSocket；恢复目标与有效登录数据 | 自动发现端口、多端口联动、复杂 HMR 地址映射均留待后续版本 |

用户已确认：首版只操作已有 Agent。工作区和 Agent 由现有电脑或远端 herdr 流程预先准备，手机负责继续任务、发送 prompt、终端交互和检查项目效果。创建 Agent 不再是本轮待定项。

### SSH 配置与配对

用户已确认首版采用结构化手动配置：填写主机、用户名、端口及可选 HTTP CONNECT 网关，使用手机独立公钥，提供远端登记命令和连接测试。SSH config 导入留待后续版本。

开发机配置包括名称、SSH 主机、端口、用户名、连接方式和可选 herdr socket 地址。连接方式提供直连或 HTTP CONNECT；后者填写网关主机和端口，不要求用户输入 shell 命令。端口范围为 1–65535，默认 SSH 端口为 22，主机及用户名不能为空。高级 socket 地址为空时使用远端用户默认位置。

用户当前配置可映射为：SSH 主机 `tanglei.azshentong.com`、用户 `tanglei`、端口 22，HTTP CONNECT 网关 `frps.dev.azshentong.com:32083`。这些是用户配置示例，正式 App 不预置个人开发机。Mac 的 DynamicForward 11080 所承担的项目访问需求，由 App 内预览通道满足。

首次配对展示手机公钥与指纹，提供公钥复制和远端登记命令复制。登记命令需支持重复执行，保留已有 authorized_keys，首次修改前备份，并设置合适的目录、文件权限。用户在已有可信终端执行；返回 App 后点“测试连接”。首版不依赖 Mac 私钥，也不自动修改远端登录权限。

手机密钥在本机 Keychain 保存并稳定复用。读取或保存失败时给出明确错误，不能悄悄生成另一把密钥导致原配对失效。删除某台开发机仅删除该开发机的本地配置及相关凭据、草稿和预览记录；手机身份密钥可供其他已配对开发机继续使用。远端撤销权限需要删除对应公钥，配对页提供识别和撤销说明。

首次建立 SSH 时展示服务器主机指纹，并允许用户与可信电脑上的指纹核对后确认。已信任指纹变化时阻止继续认证，展示旧、新指纹及明确的重新信任入口，不能通过自动重连绕过确认。

连接测试依次反馈“网关/网络 → SSH 握手及主机校验 → 用户认证 → herdr 探测”。只有 herdr ping、兼容性检查和工作区快照读取成功后，才将 Agent 控制状态标为可用。认证失败指向公钥登记或凭据问题；找不到 herdr/socket 时提供远端检查步骤。App 不自动安装、升级或启动服务。

### Agent 操作

Space 沿用现有 UI 名称，对应远端 workspace；Agent 对应远端 pane，名称只是显示信息。列表按工作区筛选，展示服务器实际提供的名称、类型及状态，区分“没有 Agent”和“连接尚未恢复”。

选择 Agent 后进入原生终端。中文、多行 prompt 使用输入框发送；Esc、Tab、方向键、Enter、Ctrl+C 使用控制键发送。Ctrl+C 按用户明确点击执行。首版保留已有普通终端入口，普通终端输入不冒充 Agent prompt。

草稿按开发机和 pane 分开保存。切换 Agent、切后台、锁屏及冷启动后回到对应草稿。发送中禁用重复提交；服务端确认接收后清空该次草稿，确认接收不等于任务已经完成。可判定尚未发出的失败保留草稿供重试；可能已送达但未收到确认的请求标为“发送结果待核对”，由用户核对终端后决定再次发送。重连不自动重发 prompt 或控制键。

进程仍在时，恢复期间保留原终端和草稿，显示“正在恢复连接/终端”。终端重新可用后开放发送。真正未选择 Agent 时才显示选择提示；已有选择但尚未恢复时显示恢复状态。已选 pane 被远端删除时，提示该 Agent 已不存在，保留可取回的草稿并让用户重新选择。

原型使用现有 attach takeover 行为。正式版本需要用同一 Agent 的电脑与手机同时连接，验证终端尺寸和控制权变化；若服务端限制同时附着，应明确告知用户，并提供接管操作，不能将这种服务端约束显示为普通断网。

### App 内预览

用户已确认以下范围符合日常使用：手动端口或完整 URL、保存名称并关联工作区、每次一个活动预览、网页导航和 API/WebSocket，以及锁屏后恢复地址和有效登录状态。自动发现端口、多端口联动留到后续版本。

预览有两个入口：

1. **SSH 端口预览**：选择开发机，输入远端端口；默认目标为该机的 127.0.0.1。App 建立私有转发入口，再用内置网页视图打开，项目服务无需新增公网暴露。
2. **URL 预览**：输入完整 HTTP/HTTPS URL，使用手机网络直接访问；HTTPS 按正常证书规则校验。此模式不隐式改为经 SSH 访问。

预览可保存名称并关联工作区，便于在该项目的 Agent 与网页之间切换。目标身份包含开发机、访问模式和远端地址；不同目标的浏览数据和恢复路径应隔离。首版允许保存多个目标，每次只保持一个活动预览。

提供返回、前进、刷新、关闭键盘及回到 Agent 的操作。记住最后访问的可恢复 URL/path/query/fragment 和网页存储、登录数据；返回前台时在可达通道上恢复页面。恢复期间保留现有画面或显示明确的恢复状态。网页进程终止或 App 冷启动时允许重新加载，不保证网页内存里的未提交表单、滚动位置和任意 JavaScript 状态全部复原。

SSH 预览必须覆盖 HTML、静态资源、相对路径 HTTP API 和同源 WebSocket。HMR 使用同源 WebSocket 时纳入验收。页面若把 API/HMR 固定为手机不可达的绝对 localhost 地址或另一端口，App 提示检查服务地址、Host/Origin 和 HMR 配置；首版不通过重写项目代码或网页响应来掩盖地址配置问题。

HTTP 服务未启动、远端拒绝端口、SSH 中断、网页 TLS 错误应有可区分的失败提示和重试入口。预览失败不清空 Agent 选择或草稿，也不停止远端项目。多个资源并发加载时，终端与 prompt 操作仍须可用。

## User Stories

以下用户故事细化已确认的三个产品方向；后续版本扩展不作为首版必需故事。

1. As a 远端开发者, I want 保存开发机名称、主机、端口和用户名, so that 我能在手机上重复连接同一环境。
2. As a 远端开发者, I want 配置直连或 HTTP CONNECT 网关, so that 我能使用与现有电脑相同的可达路径。
3. As a 远端开发者, I want 输入时发现缺失字段和无效端口, so that 我能在连接前修正配置。
4. As a 远端开发者, I want 编辑开发机配置并重新测试, so that 网络入口变化后仍能开发。
5. As a 远端开发者, I want 保存并切换多台开发机, so that 不同项目环境不会混在一起。
6. As a 远端开发者, I want 设置可选 herdr socket 地址, so that 非默认部署也能连接。
7. As a 远端开发者, I want 手机生成并保存独立公钥身份, so that 我能单独管理手机的登录权限。
8. As a 远端开发者, I want 查看公钥和指纹, so that 我能识别正在登记的设备身份。
9. As a 远端开发者, I want 复制安全、可重复执行的公钥登记命令, so that 我能通过已有电脑完成配对。
10. As a 远端开发者, I want 配对后测试完整 herdr 连接, so that 我能确认手机已经可以操作 Agent。
11. As a 远端开发者, I want 首次连接时核对并确认服务器指纹, so that 我能连接到预期开发机。
12. As a 远端开发者, I want 指纹变化时看到明确提示, so that 我能核对变化原因再恢复连接。
13. As a 远端开发者, I want 区分网关、认证及 herdr 错误, so that 我能执行对应的修复步骤。
14. As a 远端开发者, I want 手机密钥读取失败时保留原配对信息, so that 我不会因静默换钥被迫重新登记。
15. As a 远端开发者, I want 删除本地开发机配置并查看远端撤销说明, so that 我知道如何完整撤销手机访问。
16. As a 远端开发者, I want 查看工作区和已有 Agent, so that 我能继续电脑上开始的任务。
17. As a 远端开发者, I want 按工作区筛选 Agent, so that 我能找到对应项目。
18. As a 远端开发者, I want 查看服务器提供的 Agent 状态, so that 我知道任务正在执行还是等待操作。
19. As a 远端开发者, I want 打开原生终端查看实时输出, so that 我能观察开发过程和结果。
20. As a 远端开发者, I want 输入中文和多行 prompt, so that 我能完整表达开发要求。
21. As a 远端开发者, I want 发送必要控制键, so that 我能处理终端交互和主动中断当前操作。
22. As a 远端开发者, I want 使用已有普通终端, so that 我能完成非 Agent 的终端交互。
23. As a 远端开发者, I want 每个 Agent 独立保留草稿, so that 切换项目时不会误发内容。
24. As a 远端开发者, I want 提交过程中阻止重复点击, so that 一次操作不会意外提交多次。
25. As a 远端开发者, I want 区分已确认接收、发送失败和结果待核对, so that 我能决定是否重试。
26. As a 远端开发者, I want 重连后由我决定是否再次发送未确认内容, so that 开发指令不会被自动重复执行。
27. As a 远端开发者, I want 返回前台保留原终端画面和输入, so that 我能继续刚才的思路。
28. As a 远端开发者, I want App 重启后恢复开发机、Agent 和草稿, so that 系统回收不会丢掉待发送内容。
29. As a 远端开发者, I want 看到 Agent 已删除或终端附着冲突的具体原因, so that 我能选择新的操作目标。
30. As a 远端开发者, I want 网络恢复后自动尝试重连并允许手动重试, so that 临时断网不会迫使我重新配置。
31. As a 远端开发者, I want 输入远端服务端口进行预览, so that 我能检查 Agent 启动的项目。
32. As a 远端开发者, I want 在 App 内打开已有 HTTP/HTTPS URL, so that 我能使用现有可达的服务入口。
33. As a 远端开发者, I want 看到预览使用的开发机和访问模式, so that 我知道正在检查哪个环境。
34. As a 远端开发者, I want 命名保存预览并关联工作区, so that 下次无需重新输入地址。
35. As a 远端开发者, I want 使用网页返回、前进和刷新, so that 我能完成项目页面中的操作。
36. As a 远端开发者, I want 在 Agent 与预览之间快速切换, so that 我能反复提出修改并检查结果。
37. As a 远端开发者, I want 通过同一入口访问网页资源、API 和 WebSocket, so that 预览可以覆盖真实交互。
38. As a 远端开发者, I want 同源 HMR 在正常连接及恢复后工作, so that 我能及时看到代码变化。
39. As a 远端开发者, I want 同一预览目标恢复页面地址和登录数据, so that 返回前台后减少重复导航和登录。
40. As a 远端开发者, I want 不同预览目标隔离网页存储, so that 复用本地入口不会串用项目登录状态。
41. As a 远端开发者, I want 预览错误提供相应检查和重试入口, so that 我能区分服务未启动和手机连接问题。
42. As a 远端开发者, I want 预览加载时终端和 prompt 仍可操作, so that 页面请求不会阻塞开发。
43. As a 远端开发者, I want 预览重载时保留 Agent 草稿和远端任务, so that 网页恢复不会打断编码任务。
44. As a 远端开发者, I want 查看可复制且不包含凭据的连接诊断, so that 我能描述故障并协助排查。

## Implementation Decisions

### 已确认的基础

- SSH 入口采用结构化手动配置，支持直连和 HTTP CONNECT；手机独立公钥配对，通过复制登记命令及连接测试完成流程，首版不加入 SSH config 导入。
- 首版 Agent 范围限于已有目标的发现、选择、prompt、终端交互及恢复；不增加 Agent 创建、重命名、关闭或工作区创建流程。Ctrl+C 保留为已有终端的控制键，不等同于删除或关闭 Agent。
- 首版预览支持手动远端端口和完整 HTTP/HTTPS URL、命名保存并关联工作区、每次一个活动目标、网页导航及 API/WebSocket；锁屏后恢复地址和有效登录数据。自动端口发现及多端口联动不纳入首版。
- 复用 HerdrMobile、HerdrKit 的领域模型及 herdr RPC、HerdrSSH 原生传输、Ghostty 终端和 WKWebView。原型作为行为证据，正式入口移除个人环境硬编码。
- 客户端使用设备标识、workspace ID 和 pane ID 关联上下文；显示名称变化不改变草稿或选中目标。普通终端附着使用 terminal ID，与 Agent pane 目标区分。
- RPC 控制、事件订阅、终端 PTY 和预览转发是不同能力；SSH 已认证不能代表终端及预览均已可用。继续使用 ping、session.snapshot、events.subscribe、agent.prompt 和 pane.send_input 契约，不新增服务端 prompt 幂等承诺。
- 已验证环境为 herdr 0.9.1、协议 22。既有移动端协议检查以 17 为最低值；这不代表 17–21 已验证具备全部行为，正式版本按所需能力检查并给出兼容性提示。

### 首版建议的模块与接口

- **开发机配置与配对模块**：负责配置校验、设备记录、手机身份、主机信任及登记/撤销指导；提供测试连接的分阶段结果。非敏感配置使用版本化持久存储，身份和已有密码凭据保留在 Keychain。现有配置应可迁移；密码认证兼容保留，但不扩展复杂交互认证。
- **连接协调模块**：拥有每台开发机的控制、事件和终端连接生命周期；提供可用、恢复中、需用户处理及可重试错误。编辑网络/认证配置后取消旧连接，旧请求完成不能覆盖新设备状态。
- **Agent 会话模块**：拥有稳定终端表面、选择、按设备与 pane 隔离的草稿和发送状态。持久保存发送前的待确认记录；明确收到成功后完成提交。终端附着就绪与 prompt RPC 可用分别检查；恢复期间继续编辑草稿。
- **预览模块**：拥有目标记录、浏览数据存储、网页视图和活动转发；提供打开、切换、关闭、暂停、恢复和导航接口。目标身份与网页存储、稳定 origin 关联，切换目标时不能误加载上一个服务的路径或 cookie。URL 模式保留网页自身正常的站点关系。
- **SSH 转发接口**：提供有界、可取消的 TCP 流及关闭语义。RPC/PTY 与浏览器流量不能因现有独占转发驱动而相互阻塞。正式实现需要选择隔离连接或可并发通道方案，通过资源和交互验收决定；原型“每个 TCP 请求新建 SSH、最多 8 条”不是最终规格。
- **诊断模块**：记录连接阶段、错误类别、重连耗时及通道状态；日志不包含私钥、密码、prompt 正文或完整敏感 URL 查询参数。普通用户提示使用可执行的语言，协议细节放在展开的诊断中。

### 首版建议的状态与恢复契约

- 持久状态包括设备配置、信任记录、选中 workspace/pane、逐 Agent 草稿及发送确认状态、预览目标和最后可恢复地址。编辑时持续保存，后台收尾再次保存；不依赖系统一定通知进程终止。
- 短暂 inactive 保持上下文；进入 background 完成有界收尾并释放活动网络通道。前台恢复顺序为控制连接及快照 → 目标核对与事件订阅 → 终端附着；活动预览独立恢复。部分失败不能清空另一部分状态。
- 前台断线采用有界退避重试。建议每轮最多 5 次、间隔 1/2/4/8 秒；耗尽后保留画面并提供重试按钮，返回前台或网络恢复可触发新一轮。认证失败、指纹变化、协议不兼容转为待处理状态，避免无意义重试。具体时限待验收测量后确认。
- 恢复请求均可取消；切换设备、Agent 或预览目标时，旧的延迟结果和旧通道关闭回调不能污染当前页面。重连只恢复读取与附着，不重放用户写操作。
- 进程仍在时保留终端缓冲与视图；冷启动重新附着获取远端当前画面，不承诺恢复完整历史滚屏。网页数据恢复受网页持久化和登录有效期约束，不承诺恢复任意内存状态。

## Testing Decisions

### 测试入口建议，待用户确认

优先通过一个最高层入口验收：真机 App 中完成“配对 → 操作 Agent → 项目预览 → 故障后恢复”。自动化沿用真实 SSH 与 RPC 的现有集成入口，新增可重复的 HTTP/API/WebSocket 服务夹具补足预览行为；避免为每个视图单独构造模拟连接状态的测试。

现有先例包括 HerdrSSH 的 SessionDriverE2ETests（可丢弃 sshd、连接中断、TCP 转发与资源释放），HerdrKit 的 SocketRPCTests（NDJSON 与事件订阅）及 TerminalSnapshotTests（pane/terminal 关系和旧快照兼容）。测试关注用户可观察结果、真实字节流和服务端收到的操作，既有底层回归继续运行；不把内部任务数量或 SwiftUI 身份当作产品验收结果。

正式开发阶段补充重复执行的测试环境与步骤。当前仓库没有完整移动端 UI 自动化验收入口；本草案没有假定已经实现。若用户要求全流程自动化，则另加 App 层测试入口，以同一批真实服务夹具覆盖主链路。

### 验收场景

| 场景 | 外部可观察的通过条件 |
| --- | --- |
| 首次配对 | 原电脑登录仍可用；手机公钥只登记一次；App 可读取工作区和 Agent |
| 连接配置 | 直连及用户 HTTP CONNECT 路径均可测试；无效字段可修正；配置重启后保留 |
| 主机信任变化 | 首次需明确确认；变化阻止认证；自动恢复不能跳过核对 |
| 失败诊断 | 网关不可达、未登记公钥、herdr 不可用及协议不兼容有不同提示和下一步 |
| Agent 输入 | 中文、多行 prompt 到达所选 pane；正常确认路径只提交一次；控制键到达正确目标 |
| 发送时断网 | 保留草稿及待核对状态；重连不会产生第二次提交；用户能查看终端后决定重试 |
| 多设备与多 Agent | 同名或相同 pane 文本标识不会造成草稿跨开发机混用；切换后延迟结果不覆盖新目标 |
| 锁屏 30 秒 / 3 分钟 | 进程仍在时原画面保留；没有错误的 No Agent Selected 闪屏；选择与草稿保留，终端恢复后可输入 |
| Wi-Fi / 蜂窝切换、短暂断网 | 自动恢复或可手动重试；失败时保留上下文；旧数据不覆盖新连接 |
| 强制结束后重启 | 回到保存的设备、Agent、草稿和预览目标；允许重新加载终端及网页；不会自动重发 prompt |
| 远端删除 Agent | 明确提示目标已不存在；草稿可取回；能重新选择其他 Agent |
| 电脑与手机同时附着 | 记录尺寸和控制权行为；服务端要求接管时明确展示，符合确认后的产品策略 |
| 端口预览 | HTML、并发静态资源、相对 API 和 WebSocket 可用；终端和 prompt 同时可用 |
| HMR | 同源 HMR 可观察到代码更新；断线恢复后再次更新生效；独立端口配置问题有可执行提示 |
| 预览恢复与隔离 | 同目标地址和有效登录数据恢复；切换不同服务后没有串用存储或旧路径 |
| 网页进程终止 | 自动或可手动重载到保存目标；Agent 选择、草稿与远端任务不受影响 |
| 服务/网页错误 | 服务未启动、转发失败及 TLS 错误可区分；重试不会自动启动或停止项目服务 |
| 反复恢复与切换 | 连续 20 轮切换/锁屏/恢复后无崩溃、遗留监听占用或持续增长的活动连接；Agent 与预览仍可用 |

恢复体验的建议目标：进程仍在时第一帧保留原内容，并在 500ms 内给出恢复提示；在可达且稳定网络下，从回前台到 Agent 终端可交互、预览可正常请求分别以 10 秒为目标。用至少 10 轮实测记录成功率、耗时及超时原因；这是待确认的目标，原型尚未完成指标测量。网络或服务不可用时的通过条件是清晰状态、保留数据和可重试，而不是强行在时限内恢复。

原型已经通过核心链路与短时锁屏恢复。HMR、网络切换、系统终止后冷启动、多目标隔离及正式配置/配对界面仍需按本表验收，不能沿用原型“通过”标记。

## Out of Scope

三个方向的产品边界已确认；其余非核心扩展也暂不纳入本规格：

- herdr-web-ui 包装、Safari 故障修复、完整搬迁 macOS 客户端的全部功能。
- 无限后台执行、用无关音频/定位维持连接、系统级 SOCKS/VPN、让其他 App 使用本 App 的隧道。
- 自动修改远端 authorized_keys；同步或导出 Mac 私钥；完整解释并执行任意 SSH config/ProxyCommand；SSH 跳板及需账号密码的 CONNECT 代理。
- 已确认不包含 Agent 和工作区的创建、重命名、关闭；文件编辑及上传也不在首版建议范围内。
- 自动识别 Agent 输出中的服务端口、扫描开发机端口、同时保持多个活动预览，以及自动修正项目的绝对地址或多端口 HMR 配置。
- 自动启动/停止远端项目、安装/升级 herdr，新增服务端严格 exactly-once 提交协议。
- Windows/macOS 远端与 Tailcat 能力扩展；首版新能力针对已验证的 Linux SSH 路线，保留既有其他入口行为。
- 推送通知、团队共享配置、账号体系、App Store/TestFlight 发布。本轮使用个人签名真机开发，分发方式另行规划。
